# Human Approval Policy

**Status:** v1.1 | **Date:** 2026-11-18 | **Owner:** Founder | **Review:** Annual

## Purpose

Defines when and how a human (the founder) must approve AI-recommended or execution actions before they proceed.

## Approval thresholds

| Category | Threshold | Requires |
|----------|-----------|----------|
| Routine, reversible, low-cost | No monetary limit | Autonomous |
| Spending | Up to USD 100/month | Founder review if aggregated |
| Spending | USD 100–500/month | Founder review (aggregate) |
| Spending | Above USD 500/month | Founder approval |
| Irreversible actions | Any | Founder approval |
| High-impact actions | Any | Founder approval |
| Constitutional changes | Any | Founder approval |

## Escalation path

If the founder is unavailable, urgent decisions proceed under the standing authority documented in the Decision Register; if none exists, the action is paused until the founder is available.

## Approval evidence

All approvals are recorded in the Decision Register. The founder's affirmative instruction is the evidence of approval.

## Security acceptance (Rev 1.1, Amendment 6)

Production deployments require a 10-point security acceptance gate before launch. The gate checklist is maintained in `../03_SHARED_OS/02_SECURITY/Security_Constitution.md`.
