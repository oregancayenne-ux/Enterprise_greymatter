# Model Consultation Protocol

**Status:** v1.1 | **Date:** 2026-11-18 | **Owner:** Founder | **Review:** Annual

## Purpose

Defines how multiple AI models are consulted when independence and critique add value.

## When to consult

- When a decision is material and the cost of error is high.
- When a single model's output is likely to be biased by training data or prompt framing.
- When the founder requests a cross-check.

## Consultation protocol

1. Request the assessment from each model independently.
2. Do not let models see each other's outputs (no prompt leakage).
3. Record each model's opinion; do not let them converge mid-process.
4. Surface disagreements to the founder; the founder resolves.
5. Document the outcome in the Decision Register.

## Conflict resolution

- If models disagree on a material point, surface the disagreement to the founder.
- If models agree, note the consensus.
- Record the consultation outcome and the models used.
